# Git 提交规范

> 适用于本仓库所有 `git commit` 操作。

## 1. 提交信息语言（强制）

- **Description（标题）和 Body（正文）必须使用简体中文。**
- 禁止使用英文、日文或其他非中文语言。
- Conventional Commits 的 type 与 scope 仍使用英文小写（例：`feat`、`fix`、`refactor`、`docs`、`chore`、`test`、`build`、`ci`）。
- **禁止在提交信息中添加任何形式的 AI 签名或尾注**，例如：
    - `Claude`、`Codex`、`Generated by Codex`、`Generated with Claude Code`
    - `Co-authored-by: Claude`、`Co-authored-by: Codex`、`Co-Authored-By: ...`
- 不要在消息末尾附加任何作者署名 / 工具署名 / 生成来源标记。

### 1.1 标题格式

```
<type>(<scope>): <中文描述>
```

- `<type>`：英文小写，遵循 Conventional Commits。
- `<scope>`：英文小写模块名，可选（例：`api`、`core`、`plugin`、`i18n`、`build`）。
- `<中文描述>`：简洁陈述本次提交做了什么，**必须中文**，结尾不加句号。

### 1.2 正文格式

- 用空行与标题分隔。
- 使用中文撰写，可用 `-` 列出要点。
- 说明"为什么改"和"改动要点"，避免逐行复述 diff。

### 1.3 示例

✅ 正确：

```
feat(core): 新增玩家数据仓库的批量查询接口

- PlayerRepository 新增 findByUuidIn：一次查询多名玩家，减少数据库往返
- 基于 EasyQuery 的 in 条件实现，命中主键索引
- 补充单元测试覆盖空集合与重复 UUID 的边界
```

❌ 错误：标题使用英文

```
feat(core): add batch query to player repository
```

❌ 错误：正文使用英文

```
feat(core): 新增玩家数据仓库的批量查询接口

- Add findByUuidIn to PlayerRepository
- Implement with EasyQuery in-condition
```

## 2. 禁止入库的内容（强制）

以下文件**严禁**通过 `git add` / `git commit` 进入仓库：

- 任何"计划文档"：如 `PLAN.md`、`plan-*.md`、`实施计划.md`、`roadmap.md`（项目级 README 中的简短规划除外）。
- 任何"需求文档"：如 `REQUIREMENTS.md`、`需求.md`、`requirement-*.md`、`spec-*.md`、PRD 文档。
- 任何"实施/执行/分析报告"：如 `IMPLEMENTATION.md`、`实施记录.md`、`执行报告.md`、`分析.md`、`重构报告.md`、`audit-*.md`。
- AI 助手生成的过程性 Markdown 笔记（包括交流稿、思路记录、checklist 文档）。

### 2.1 例外

以下文档**允许**入库：

- 面向使用者的产品文档：`README.md`、`CHANGELOG.md`、`LICENSE`、`ARCHITECTURE.md`、`CONTRIBUTING.md`、`docs/API.md`、`docs/changelog/*.md` 等长期维护的项目文档。
- 配置/规则类：`.claude/rules/*.md`、`.claude/skills/**`、`AGENTS.md`、`CLAUDE.md`。
- 模块自身的对外说明（`<module>/README.md`）。

### 2.2 误入库时的处理

- 提交前 `git status` 自查，发现上述禁入文档应从暂存区移除（`git reset HEAD <file>`）。
- 已误入库则单独提交一次 `chore: 移除误入库的过程性文档` 删除。

## 3. 其他约束

- 一次提交只做一件事，避免无关改动混入。
- 禁止跳过 hooks（`--no-verify`、`--no-gpg-sign`）。
- 禁止对已 push 的提交做 `--amend`，应追加新提交。
- 提交前确认未包含 `.env` / 凭据 / 大型二进制等敏感或不应入库的文件。
